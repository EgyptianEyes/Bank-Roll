# Bank-Roll

European roulette simulation and street-strategy research with optional BRI persistence on PHP and MySQL/MariaDB shared hosting.

## Run and deploy

Upload `index.html`, `assets/`, `src/`, and `server/` into the cPanel web root (usually `public_html/`). Keep the directory structure intact and serve the site over HTTPS. Browser-only simulation works without a database. Persistent BRI storage requires PHP 8.1 or later with PDO MySQL and a MySQL/MariaDB database. No Node.js production service, build step, paid API, or CDN is required. Because the application uses native ES modules, use a web server rather than opening `index.html` directly from the filesystem.

Create a database and restricted database user in cPanel, then import the SQL files in `server/private/migrations/` in numeric order with phpMyAdmin. Copy `server/private/config.example.php` to a location outside `public_html` and fill in the database credentials plus a long random registration key. Configure `BANKROLL_CONFIG_FILE` to that absolute path using the hosting provider's PHP-FPM environment settings. Alternatively, supply the individual `BANKROLL_DB_*` and `BANKROLL_REGISTRATION_KEY` variables through the PHP environment. Never place real secrets in a public directory or commit them.

Provision each player through `POST /server/api/v1/register.php` using the registration-key header. The returned bearer token is shown only once; paste it into Configuration. The token stays in the current browser tab's `sessionStorage`. Shared-research consent is off by default; the Configuration checkbox updates player consent and records consent for each new session. `server/private/.htaccess` denies web access to server internals and migrations.

For browser-only local development, serve the repository root with a static HTTP server. PHP helpers can be tested with PHP CLI, and JavaScript tests use Node.js:

```sh
npm test
php tests/php/run.php
```

See [architecture](docs/architecture.md), [mathematics](docs/mathematics.md), [development](docs/development.md), and [server API](docs/server-api.md).

## Current scope

The existing interface and roulette board are retained. Live runs offer the original cold-street strategy as the default and a separate BRI Autonomous mode. Autonomous decisions drive the actual street wagers; STOP suspends wagers while the session continues observing. Every proposed wager is independently checked by bankroll accounting, and configured session stop-loss/take-profit limits still apply. The mode uses the central BRI coordinator and the CONTINUE/SWITCH/SPREAD/STOP decision engine with exact exposure projections. When server storage is enabled, forecasts and full decision snapshots are recorded before outcomes and replayed in order from the bounded offline outbox. The prediction model is exploratory and its measured accuracy is reported against the uniform European baseline; it does not establish a betting advantage, and the companion can never influence the mathematics.

The integrity monitor flags structural contradictions and statistical shift candidates without treating surprising results as verified errors. The False Entry Challenge runs isolated synthetic cases and stores aggregate benchmark reports. The Configuration panel can review and explicitly correct recent server-recorded events; corrections append revisions, preserve original events/evaluations, and invalidate derived state. The rebuild endpoint reconstructs derived statistics from the effective history idempotently, and forecasting resumes only after the client uploads a chronologically rebuilt model checkpoint. Shared aggregates require player and session consent plus an explicit shared-cohort UUID and matching table type; only corrected observed results are pooled. The current simulator records synthetic results, which are excluded from shared aggregates. Human observed-origin session creation and outcome submissions are rejected by the PHP API by default (`BANKROLL_ALLOW_OBSERVED_SUBMISSIONS=false`) until rate limiting, provenance enforcement and database integration have been verified. This is a release safety gate, not a human-observation verification system. Monetary values, stakes and progressions are bounded to exact safe-integer minor units. The schema and API are integration-tested against MySQL/MariaDB by `tests/integration/server-db.test.js`; on hosts where that suite cannot run, follow the deployment-side verification procedure in [server API](docs/server-api.md). Remaining work includes adaptive model lifecycle/holdout validation, hypothesis and experiment management, 100-spin Monte Carlo planning, a worker-backed research UI, manual/import workflows, and authentication recovery.

The live research panel now follows every resolved simulator outcome with current-dataset street profiles, a last-100 number-frequency view, forward-scored model summaries, and an in-memory timeline of significant events. It labels the simulator's data as synthetic, distinguishes sample maturity from predictive confidence, and does not claim that calibration or a hypothesis archive exists.

## Persistent Table Identity

BRI now keeps a selected table profile separate from each observation session. The active simulated table remains selected across simulation runs and browser reloads; with authenticated storage enabled, the account also stores its active table ID so another signed-in device can restore that selection. Switching tables is explicit and confirmed, retains each profile, and loads that table's own compact learner checkpoint. Clearing simulation results does not reset table-level learning. This phase only records synthetic simulator outcomes; it does not yet provide human live entry, historical imports, pause/gap markers, observer or dealer handovers, live cadence limits, or quarantine. A table profile and a shared cohort ID are identifiers, not independent proof of a physical wheel or human observation. See the [observation-integrity report](BANK-ROLL-OBSERVATION-INTEGRITY-REPORT.md) for implemented scope and next steps.

## Beyond Frequency: Can History Predict the Future?

Bank-Roll investigates two distinct questions. First, do outcomes occur at frequencies different from the theoretical European-wheel baseline? Second, does the ordered history contain information that improves a forecast made before the next outcome? A sequence can be well balanced overall and still have dependencies; an independent sequence can also contain striking-looking streaks and temporary imbalances. Neither a frequency deviation nor a retrospective pattern alone establishes predictability.

The current simulator uses a deterministic Mulberry32 pseudorandom generator initialized from a 32-bit FNV-1a hash of the configured seed. It maps a draw to a number with `floor(draw * 37)`; zero is a valid outcome. The generator maintains one 32-bit state and does not inspect prior roulette outcomes, suppress repeats, or balance frequencies. Seeded research is reproducible and is not cryptographically secure randomness. Reproducibility is useful for controlled experiments, but it does not establish how a real wheel, online RNG, or another software generator behaves. The UUID facility used for research record identifiers is separate from outcome generation.

An ideal independent wheel gives each number probability `1/37`, each street `3/37`, and zero `1/37`. Frequency tests address marginal distribution. Independence tests would instead ask whether past outcomes change conditional future probabilities, for example through lagged transitions or repeat rates. A historical transition table can look unusual by chance, especially after searching many lags and categories; a proposed relationship must be specified, forecast chronologically, scored against uniform and existing models, and validated on independent data before it can support a conclusion.

Current implementation includes reproducible uniform, independent-biased, and changing-distribution synthetic experiments, plus prequential forecasts scored after their outcomes. These tests do not yet include repeat-suppressed, streak-suppressed, frequency-balancing, Markov-dependent, periodic, or blind predictability-challenge generators. The research lab has million-spin synthetic frequency experiments, but no integrated million-spin sequence-dependence benchmark has been run. No current evidence establishes sequential predictability or a betting edge. A single-street wager breaks even at `1/12` (about 8.3333%), above the fair-wheel probability `3/37` (about 8.1081%); a detected dependency would still need reliable forward conditional probabilities and risk-approved financial evaluation.

The current Randomness Integrity audit and staged work are documented in [BANK-ROLL-RANDOMNESS-INTEGRITY-REPORT.md](BANK-ROLL-RANDOMNESS-INTEGRITY-REPORT.md). Next steps are incremental transition/streak statistics, controlled dependent generators, blind multi-seed evaluation, chronological model comparisons, and only then payout-aware actionability analysis. False-positive control and independent validation take priority over making BRI more active.
