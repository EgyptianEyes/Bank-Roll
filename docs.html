01 / SETUP

Getting Started

Requirements

The browser application uses HTML, CSS and native JavaScript ES modules. A web server over HTTPS is required; opening the page as a file:// URL is not supported. Browser-only simulation and Test Mode do not require a database. Persistent account storage uses PHP 8.1+ with PDO MySQL and MySQL/MariaDB. Node.js is used for development tests and research scripts, not as a production service.

cPanel installation

Upload the intended public files while preserving the assets/, src/ and server/ directory structure. Keep the root and private .htaccess files. Configure database credentials and the registration secret outside the web root using BANKROLL_CONFIG_FILE or PHP environment variables. Never put real credentials in the shipped example configuration.

When provisioning persistent storage, import migrations 001 through 006 in numeric order into a backed-up database. Migration 006 adds an account active-table pointer. Database integration for the latest migrations was not verified in the current development container because PDO MySQL is unavailable.

Operating modes

The current site provides a simulated live laboratory, a separate browser-only Test Mode, and structured research scripts. Public human Live Observation entry and CSV/historical import are not yet implemented. The PHP server rejects observed-origin session creation and writes by default unless its private BANKROLL_ALLOW_OBSERVED_SUBMISSIONS setting is explicitly enabled; do not enable it until the missing safeguards are built and verified.

02 / LIVE OBSERVATION

Human Observation

Current status

There is no public manual live-entry UI in this version. The persistent table profile system applies to simulated profiles; it separates a table identifier from observation-session identifiers and can restore table-specific model state. This identity does not prove that a particular physical wheel was watched or that a sequence was uninterrupted.

Continuity and observer changes

Pause/resume markers, missing-spin declarations, sequence-continuity metadata, observer/dealer/player handover records, and conflicting-stream reconciliation are planned, not implemented. Until these exist, the system must not infer that results across a human observation break are adjacent spins.

Submission safeguards

Observed-origin API submissions are disabled by default on the PHP backend. There is no verified atomic live cadence limiter, suspicious-submission quarantine, observer authentication workflow or administrator review queue. Authentication, provenance labels and a cohort UUID alone do not prove that data is genuine.

03 / TEMPORARY SANDBOX

Test Mode

Data handling

Test Mode runs in a dedicated page using an isolated `TestModeSession` and the real BRI coordinator, predictor, event stream, bankroll safeguards and companion. It labels all results `sourceType=test` and synthetic. It has no database client, fetch calls, localStorage, sessionStorage or IndexedDB access and uses no live table ID.

Limits and expiry

A session accepts at most 5,000 outcomes; generated batches are limited to 100. Its deadline is fixed at creation plus 24 hours and activity/reset never extends it. End/discard clears session arrays, coordinator, event stream and companion state; page navigation discards the in-memory session. It cannot be resumed after a reload and is not included in server backups.

Forecast chronology

For each manual or generated result, the coordinator prepares the next forecast and decision first, then processes the outcome and scores the forecast. Corrections replay only the temporary test sequence. Nothing from this page enters live table profiles, shared aggregates, public findings or persistent archives.

04 / EXPERIMENTS

Research Laboratory

Structured simulations

The research scripts run seeded uniform, biased and changing-distribution synthetic scenarios and compare existing production strategies on common sequences. The autonomous research laboratory supports cancellation and bounded aggregate reports; benchmark JSON is retained in the development repository and is blocked from direct web access.

Historical datasets and imports

CSV imports, large historical-data upload, column mapping, import preview, retrospective replay and export UI are not implemented. A provided in-memory sequence can be used by existing research APIs, but is not an import workflow or prospective live evaluation.

Research retention

Structured experiment results are distinct from Test Mode's disposable memory and from any future human live-observation archive. Test Mode's 24-hour expiry does not apply to research-result files. Public experiment pages and a persistent experiment catalogue are not yet implemented.

05 / SOFTWARE

BRI Architecture

Observation and learning

StreetTracker incrementally maintains twelve street totals, gaps, streaks and a bounded rolling history. StreetPredictionEngine issues forecasts after its warm-up, evaluates stored candidate distributions after outcomes and maintains model scores. BriCoordinator stages forecast and decision before the outcome, then scores/learns and settles using existing exact-cent accounting.

Strategy and finances

decision-engine.js compares CONTINUE, SWITCH, SPREAD and STOP under common limits. accounting.js independently validates the proposed simulated wager and settles exact integer pence. Strategies and forecasts are exploratory; they do not establish positive expected value.

Persistence

The optional PHP API uses bearer tokens whose hashes are stored server-side, prepared SQL statements, owner-scoped records, append-only correction history and migrations 001–006. The browser has a bounded offline outbox. PHP/MySQL integration for this exact release is not verified here because PDO MySQL/test DB settings are absent.

06 / SEQUENCE RESEARCH

Randomness Integrity

Uniformity is not independence

Uniformity describes marginal frequencies; independence asks whether the past changes conditional probabilities for the next outcome. The current simulator uses seeded Mulberry32 and `floor(draw * 37)` for reproducible outcomes. It does not inspect history, and it is not cryptographic randomness.

What is implemented

Current research tracks frequency and forward scores for fixed frequency models. Dedicated lagged transition tests, streak-null comparisons, periodicity controls, conditional models and a blind predictability challenge are not implemented. The finite-grid mapping remainder and current audit scope are described in the linked Randomness Integrity report in the repository, not as a public finding about commercial systems.

07 / EVALUATION

Statistical Methodology

Proper scores and baseline

The prediction engine scores 13 categories (twelve streets and zero) with multicategory Brier score after each forecast's outcome. The uniform European baseline assigns 3/37 to each street and 1/37 to zero. A Brier improvement measures forecast quality, not profitability.

Calibration and uncertainty

The current UI does not provide a complete calibration curve or independent holdout assessment. Evidence-Gated uses an anytime-adjusted paired Brier comparison against uniform, but the model family and validation remain limited. Do not equate observation count, a candidate anomaly or a sample win rate with confidence.

Repeated testing and false positives

Searching many streets, windows, lags and hypotheses increases the chance of finding an apparent pattern by chance. Sequence-dependence tests and their multiple-comparison controls have not yet been implemented. Any future claim must identify its test family, validation split and false-positive performance.

Expected return

For a single street with conditional win probability p, expected net return per unit is 12p - 1; break-even is 1/12. The fair baseline is 3/37 and has a -1/37 expectation. Estimated conditional probabilities require uncertainty and prospective validation before financial interpretation.

08 / TRUST BOUNDARY

Data Integrity

Provenance and corrections

The schema distinguishes synthetic and observed origin; corrections append revisions and trigger derived-state rebuilds. The client-reported False Entry Challenge remains marked unverified. A provenance label is metadata, not independent proof of source authenticity.

Live safeguards

Observed-origin sessions and submissions are rejected by default unless the private server flag is enabled. There is no production-ready human cadence rate limit, quarantine queue, import parser or admin review system. Keep `BANKROLL_ALLOW_OBSERVED_SUBMISSIONS=false` until those controls and the MySQL integration path are built and verified.

Authentication and output

Persistent API routes require a bearer token; queries are scoped to the authenticated owner and user-facing dynamic text uses text nodes. The browser API client restricts its configured URL to same-origin HTTPS outside localhost. A full third-party security audit has not been performed.

09 / SHARED DATA

Collective Intelligence

Consent and cohorts

The optional aggregate endpoint requires player-level and per-session consent, observed origin, a caller-owned cohort UUID and matching roulette table type. It returns aggregate street totals, not per-player or per-table details. The current simulator writes synthetic data and is excluded.

What a cohort does not establish

A cohort UUID is a grouping key, not proof that contributors observed the same physical table or the same consecutive spins. Conflicting observer streams, independent physical identity checks, and sequence reconciliation are future work.

10 / PUBLICATION

Living Website and Documentation

Current pages

The site currently has the simulator, a static research/methodology page, FAQ and technical guide. The live research panel updates from the browser's current synthetic dataset. No persistent public research journal, hypothesis archive or dynamic experiment catalogue exists.

Evidence-protected publishing

FAQ and technical documentation are authored static files. Search filters existing text in the browser. There is no automatic documentation-writing, content proposal, administrator editorial workflow or publication API; user data cannot directly update these pages.

Future governance

Any future research publishing should bind claims to eligible evidence, provenance, method and model version, keep revisions/audit history, and require human approval for new scientific or financial conclusions. No autonomous publishing authority is enabled.

11 / DEVELOPMENT

Developers

Repository layout

Core roulette/math and seeded randomness are in `src/core/`; incremental tracking is in `src/observation/`; models and orchestration are in `src/intelligence/`; wager logic is in `src/strategies/` and `src/bankroll/`; simulation and experiment runners are in `src/simulation/`; browser presentation lives in `src/ui/`; the optional API client is in `src/storage/`.

Test commands

npm test
npm run test:php
find server tests/php -name '*.php' -print0 | xargs -0 -n1 php -l

The MySQL integration test requires a disposable database, PDO MySQL, and `BANKROLL_TEST_DB_*` variables. A skipped run is not DB verification. The local suite currently has one such environment-dependent skip.

Security-sensitive configuration

Keep real PHP database/registration secrets outside the web root. The root and private `.htaccess` rules are intended for Apache/cPanel. This container does not include Apache's config checker, so validate those directives on the target host before deployment.

12 / REPRODUCIBILITY

Research Reproducibility

Seeds, scenarios and outputs

Existing benchmark scripts derive deterministic streams from documented seed strings and retain scenario/configuration metadata and sequence hashes. The generator is deterministic Mulberry32 seeded from a 32-bit FNV-1a reduction and is not cryptographically secure. Research result JSON in the development tree contains synthetic analysis artifacts and is not served as public evidence.

Independent replication

A seed and configuration make a synthetic experiment repeatable; they do not make a result independent or validate its assumptions. An independent researcher should reproduce the generator, inputs, model version, chronological split, scoring procedure and exclusions before treating a claim as confirmed.
